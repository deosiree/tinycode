# Feature Specification: CSV 词条英文翻译与消歧

**Feature Branch**: `001-csv-term-translation`

**Created**: 2026-11-22

**Status**: Draft

**Input**: User description: 为指定 UTF-8 CSV 中的新词条生成英文翻译，参考术语工作簿，输出翻译后的 CSV、增量参考资料，并通过人工审核处理歧义和翻译冲突。

## Clarifications

### Session 2026-11-22

- Q: 比较两个候选是否可能代表不同实体时，应基于哪些原始信息评估相似度？ → A: 对中文词项生成 embedding 稠密向量并计算语义相似度，以 0.7（含）为阈值识别语义相近的近义词候选；相似度只用于提示人工审核，不自动判断实体或修改译文。
- Q: 仍有词条等待人工审核时，系统应如何处理翻译 CSV 输出？ → A: 生成包含所有当前候选译文的草稿 CSV，并标记为未完成；待审候选也会暂时写入草稿，同时新增“审核状态”列标识各词条审核状态。
- Q: “审核状态”列是否只记录 CSV 译文的审核，而把增量术语文档的审核作为翻译完成后的独立步骤？ → A: 状态列只跟踪 CSV 译文：无需人工判断的记录标为“无需审核”，存在歧义或冲突的记录标为“待审核”，获批后标为“已批准”。术语增量另行审核，不阻止 CSV 完成。
- Q: 当词条由多个单词组成时，系统应如何将匹配到的词级术语译法组合成完整的英文词条？ → A: 优先匹配参考资料中的完整词条；没有完整匹配时，使用 jieba 对中文词条分词，复用命中的词级译法并结合 comment 和使用场景组织自然英文。词条通常是 UI 片段，不要求符合完整中文句子的语法；无法确定语义时进入人工审核。
- Q: 是否应将参考工作簿中的中文术语加入 jieba 自定义词典，以便分词时保留领域词组？ → A: 将参考资料中的中文静态术语加入 jieba 自定义词典；若术语字段“伪代码术语”的值为“是”，则不加入词典，而是根据参考备注、comment 和使用场景判断具体译法。
- Q: 一行 CSV 词条被 jieba 分成多个词，若其中任意一个词需要人工审核，这一整行是否应标记为“待审核”？ → A: 是。任一组成词待审，整行标为“待审核”；全部相关审核决定完成并批准后，整行标为“已批准”。
- 用户补充：将参考工作簿作为仓库内版本化资产维护，使不同机器检出仓库后使用相同参考资料；运行时只读，不直接修改该资产。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 翻译 CSV 中的新词条 (Priority: P1)

用户提供待处理的 UTF-8 CSV。系统读取词条、comment 和来源等信息，结合指定术语参考工作簿生成英文候选，并输出输入文件的副本，更新“英文翻译”列并增加“审核状态”列。待审候选可以出现在草稿中，但必须标记为未完成；原文件及其他输入列、行顺序和记录数量保持不变。

**Why this priority**: 生成完整、可回写的英文翻译文件是该工具的核心价值。

**Independent Test**: 使用包含词条、comment、来源及“英文翻译”列的小型 UTF-8 CSV，验证输出文件逐行对应输入、原列顺序和值均保留、“英文翻译”按候选更新且存在“审核状态”列，待审候选标记为未完成。

**Acceptance Scenarios**:

1. **Given** 用户选择一个包含 `词条`、`comment`、`词条来源` 和“英文翻译”列的有效 UTF-8 CSV，**When** 用户启动翻译，**Then** 系统读取这些列；词条单词、comment 和使用场景匹配参考资料时采用其中的英文译法，否则生成英文候选，并将所有候选写入输入文件副本的“英文翻译”列，同时新增或更新“审核状态”列。
2. **Given** 中文词条没有完整词条级参考匹配，**When** 系统需要识别其中的术语，**Then** 系统使用 jieba 对词条分词、复用适用的词级参考译法，并根据 comment 和使用场景组织完整自然英文；系统不把词条当作必然符合中文句法的完整句子，无法确定含义时将其交给人工审核。
3. **Given** 参考术语的“伪代码术语”字段为“是”，**When** 系统准备 jieba 自定义词典并翻译该词条，**Then** 系统不把该术语作为静态词条加入词典，而是结合参考备注、comment 和使用场景决定具体译法；例如 `xxx配置` 在“作为列名时可省略‘配置’”的说明和列名语境下可译为 `Platform Tool`。
4. **Given** 用户在另一台机器上检出本仓库，**When** 用户运行词条翻译，**Then** 系统从仓库内的 `assets/glossary/常用注意要点清单.xlsx` 读取相同版本的参考资料，无需访问原机器上的个人目录。
5. **Given** 输出文件已经存在，**When** 用户重新处理相同输入，**Then** 系统按照确定的输出命名规则更新该输出文件，不修改输入 CSV，也不产生多个含义相同的输出副本。
6. **Given** CSV 的编码无效、必需列缺失或文件无法解析，**When** 用户启动翻译，**Then** 系统说明具体问题，不生成看似完整的翻译结果。
7. **Given** 存在 CSV 译文待处理审核或空翻译，**When** 系统执行完成检查，**Then** 系统保留包含候选译文的草稿、标明任务未完成并列出相关记录；**Given** 所有非省略词条均有非空译文且 CSV 译文审核均已完成，**When** 系统执行完成检查，**Then** 系统将 CSV 结果标记为完成，即使增量术语文档仍待人工审核。

### User Story 2 - 审核实体歧义与翻译冲突 (Priority: P1)

用户审核系统检测出的词条歧义和翻译冲突。系统将相同单词及相同 comment 视为同一翻译语境，要求其最终翻译一致；对不同单词，或单词相同但 comment 不同却得到相同翻译的情况，系统提供冲突关系与候选供人工判定。所有候选可先显示在草稿中；待审候选必须标记为未完成，未经人工批准不得视为最终译文。

**Why this priority**: 错误合并或不一致翻译会改变词条含义，直接影响用户对术语的识别。

**Independent Test**: 构造相同单词和 comment 但翻译不同、以及不同语境词条得到相同翻译的样例，确认系统要求审核，只有获批决定才会应用到输出文件。

**Acceptance Scenarios**:

1. **Given** 相同单词和相同 comment 出现多个英文翻译，**When** 系统检查翻译结果，**Then** 系统将它们作为同一语境冲突提交审核，并要求确定统一翻译。
2. **Given** 不同中文词项得到相同英文翻译，或相同中文词项在不同 comment 下得到相同英文翻译，**When** 系统检查实体歧义，**Then** 系统展示相关记录和使用场景；对不同中文词项，系统使用 embedding 稠密向量语义相似度识别近义词候选，相似度达到 0.7（含）时提示人工判断是否为同一实体，低于 0.7 时建议采用不同翻译；相同中文词项但 comment 不同的冲突不依赖相似度阈值。所有情况都须经过 HITL。
3. **Given** 人工判定两个候选不是同一实体，**When** 系统准备修改为不同翻译，**Then** 系统先展示拟议变更并等待批准；未经批准不得标记为已批准或最终译文，但可将候选和待审状态写入草稿 CSV。
4. **Given** 人工确认两个候选可视为同一实体，**When** 系统完成审核，**Then** 系统允许它们使用相同翻译并记录审核决定。
5. **Given** 系统创建人工审核事项，**When** 展示待审词条，**Then** 每条记录包含：`单词: string`、`comment: string`、`词条来源: string`、`翻译: string`、`翻译描述: string`、`使用场景: string`、`utf-8的字节长度: number`、`字符长度: number`。关联冲突的两条或多条记录必须在同一审核事项中可识别。
6. **Given** 一行译文的所有组成词均无须人工判断，**When** 系统生成草稿，**Then** 该行“审核状态”为`无需审核`；**Given** 一行译文的任一组成词存在待人工判断的歧义或冲突，**When** 系统生成草稿，**Then** 整行状态为`待审核`；**Given** 用户已完成并批准该行所有待审词语的决定，**When** 系统更新结果，**Then** 该行状态为`已批准`；拒绝一个实体合并候选后，在替代译文获批前状态仍为`待审核`。

### User Story 3 - 产出高频未知词条的参考资料增量 (Priority: P2)

翻译过程中，系统统计未能在参考资料中找到适用条目的单词及语境。达到高频门槛的未知词条被整理为一份独立的增量参考资料，供用户审核后再补充到正式术语工作簿；系统不直接修改用户提供的原始参考工作簿。

**Why this priority**: 增量资料让人工审核结果可以沉淀为后续可复用的术语规范。

**Independent Test**: 输入包含重复未知词条的 CSV，验证达到门槛的单词及其语境被输出到单独的增量资料中，且原始参考工作簿未被修改。

**Acceptance Scenarios**:

1. **Given** 未知单词及其相同 comment 在本次输入 CSV 中出现至少 3 次，**When** 翻译结果准备完成，**Then** 系统在增量参考资料中列出该词、候选翻译、描述和使用场景，供人工审核。
2. **Given** 未知单词未达到高频门槛，**When** 系统生成增量资料，**Then** 系统不将它作为高频新增术语提交，但仍完成该条目的英文翻译或必要审核。
3. **Given** 增量资料已生成，**When** 用户审核并补充正式参考资料，**Then** 原始工作簿的修改由用户决定并执行，当前功能只生成候选增量。

---

### Edge Cases

- CSV 含有 UTF-8 BOM、引号包裹的逗号/换行、空字段或重复记录时，系统仍须正确识别记录边界并保留非目标数据。
- “英文翻译”列不存在或输入必需列缺失时，系统不得自行猜测列的含义。
- 词条或 comment 为空、词条包含多个词、标点、缩写或大小写变体时，系统须保留原始词条并将无法确定的语境交给审核。
- 参考工作簿不存在、必需 sheet 缺失或术语表对同一语境给出冲突翻译时，系统须报告缺失/冲突并避免默默采用任意候选。
- 输出文件路径与输入路径相同、输出目录不可写或写入失败时，输入文件不得被部分覆盖；若输入已有“审核状态”列，输出更新该列而不重复添加。
- 翻译候选未完成审核或存在未解决冲突时，系统须明确标识结果未完成；完成检查不得把待审条目计为已翻译。
- UTF-8 字节长度按最终英文翻译的 UTF-8 编码字节数计算；字符长度按最终翻译的 Unicode 字符数计算。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 用户 MUST 能指定一个 CSV 文件作为唯一的本次词条输入文件；输入文件 MUST 是有效 UTF-8 编码。系统 MUST 将无效编码作为输入错误报告。
- **FR-002**: 系统 MUST 从输入 CSV 的 `词条`、`comment`、`词条来源` 列读取待翻译文本、语境说明和来源。
- **FR-003**: 系统 MUST 只将目标语言设为英文，并 MUST 写入 CSV 的“英文翻译”列。
- **FR-004**: 系统 MUST 以输入 CSV 为基础生成独立输出副本，保留输入列、列顺序、记录顺序及记录数量；只允许更新“英文翻译”和已有的“审核状态”列。若输入不存在“审核状态”列，系统 MUST 在末尾新增该列。系统 MUST NOT 覆盖输入文件。
- **FR-005**: 默认输出位置为输入 CSV 所在目录，文件名为原文件名加 `_translated` 后缀并保留 `.csv` 扩展名。若目标文件已存在，本次处理 MUST 对同一目标执行可重复更新，不生成额外副本。
- **FR-006**: 系统 MUST 将仓库内版本化资产 `assets/glossary/常用注意要点清单.xlsx` 作为翻译参考，并读取以下工作表：`注意要点_中英`、`翻译简写说明`、`要注意的Comment（研发人员加）`、`翻译省略`。路径 MUST 相对于仓库根目录解析，不得依赖某台机器上的个人目录。运行时 MUST 只读该资产；参考资料更新通过正常的文件修改、审阅和 Git 提交进行。
- **FR-007**: 系统 MUST 将参考资料中存在且词条、comment 与使用场景匹配的术语翻译作为优先候选，并遵循参考资料中的缩写、大小写、用词和省略规则。
- **FR-008**: 系统 MUST 优先查找与完整词条、comment 和使用场景匹配的参考译法；无完整匹配时，MUST 使用 jieba 对中文词条进行分词，并在分词与 comment 相同的语境下保持英文翻译一致。适用的中文静态术语 MUST 加入 jieba 自定义词典以保持领域词组完整；参考条目字段“伪代码术语”为“是”的词 MUST 排除在自定义词典外，并依据参考备注、comment 和使用场景判断译法。系统 MUST 结合上下文组织完整、自然的英文译文，不得假设词条是符合中文句法的完整句子。若参考资料或输入中同一语境存在多个不同翻译，系统 MUST 创建审核事项，不得自行选择并静默覆盖。
- **FR-009**: 系统 MUST 检测不同中文词项获得相同英文翻译、或相同中文词项在不同 comment 下获得相同英文翻译的候选冲突。对不同中文词项，系统 MUST 使用 embedding 稠密向量语义相似度识别近义词候选，达到 0.7（含）时标记为语义相近；对相同中文词项但 comment 不同的冲突，系统 MUST 直接按语境冲突提交人工审核，不以相似度判断替代语境审核。系统 MUST 提供相关记录和使用场景供人工审核。
- **FR-010**: 对不同中文词项，相似度达到 0.7（含）时，系统 MUST 提示人工判断是否为同一实体；相似度低于 0.7 时，系统 MUST 建议采用不同翻译。无论相似度结果如何，所有翻译冲突 MUST 保留人工审核；相似度 MUST NOT 自动判定实体关系或修改译文。系统 MAY 将未经批准的候选写入草稿 CSV，但 MUST 在“审核状态”中标记为待审，且不得将其作为已批准或最终译文。任何消除冲突的译文变更 MUST 在标记为已批准前经人工批准。人工拒绝“同一实体”判断后，系统 MUST 提出不同翻译并再次等待变更批准。
- **FR-011**: 每个审核事项 MUST 向人工提供 `单词`、`comment`、`词条来源`、`翻译`、`翻译描述`、`使用场景`、`utf-8的字节长度` 和 `字符长度` 字段，字段类型分别为 string、string、string、string、string、string、number、number。描述或场景无法从输入和参考资料取得时，系统 MUST 留空对应字符串并将事项标记为缺少上下文，不能编造内容或自动完成审核。
- **FR-012**: 系统 MUST 统计本次输入 CSV 中未匹配到适用参考条目的单词及相同 comment 的出现次数；出现次数达到 3 次（含）即视为高频。
- **FR-013**: 系统 MUST 将达到高频门槛的未知词条候选输出为独立的增量参考文档，结构遵循参考工作簿中适用的术语格式，至少含单词、候选英文翻译、翻译描述及使用场景。系统 MUST NOT 直接更改原始参考工作簿。
- **FR-014**: 系统 MUST 在结束前逐条检查所有非省略词条的“英文翻译”是否非空，并确认 CSV 译文所需的人工审核均已完成。存在空翻译或 CSV 译文待审时，系统 MUST 将 CSV 标记为未完成并列明记录；仅增量术语文档待审不阻止 CSV 标记为完成。
- **FR-015**: 每条输出记录 MUST 在“审核状态”列使用以下状态之一：`无需审核`、`待审核`、`已批准`。若该行译文的所有组成词都无须人工判断，标记为`无需审核`；若任一组成词存在歧义或翻译冲突需要 HITL，整行标记为`待审核`；该行所有相关审核决定完成并批准后，标记为`已批准`。被拒绝后等待新候选批准的整行保持`待审核`。只要存在`待审核`记录，输出 MUST 标记为草稿/未完成。
- **FR-016**: 系统 MUST 将符合静态术语条件的参考词条加入 jieba 自定义词典；参考字段“伪代码术语”的值为“是”时 MUST 排除该词条。被排除的词条 MUST 依据参考备注和输入语境判断其翻译，不能因词条本身存在参考英文值而将该译法无条件应用于所有语境。

### Key Entities *(include if feature involves data)*

- **CSV 词条记录**: 输入中的一行数据，包含词条、comment、来源、现有列值及待写入的英文翻译。
- **词条单词**: 从词条文本分出的待翻译单词；其原始文本与 comment/使用场景共同参与语境区分。
- **参考术语**: 参考工作簿中的中文词条、英文翻译、“伪代码术语”标记、comment、翻译说明或省略规则；静态术语可作为 jieba 自定义词典词条，标记为伪代码术语的条目依赖语境决定译法。
- **翻译候选**: 针对某个词条单词及其 comment/使用场景生成或从参考资料匹配的英文译法。
- **人工审核事项**: 一项需要用户确认术语语境、实体关系或翻译变更的审核任务，包含规定的审核字段和相关冲突记录。
- **增量参考条目**: 输入中达到高频门槛、尚未在参考资料找到适用条目的单词及其候选翻译和说明。
- **翻译输出文件**: 输入 CSV 的独立副本，更新“英文翻译”列，并包含逐条“审核状态”；存在 CSV 译文待审记录时为草稿/未完成状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对有效输入文件，输出 CSV 保留全部输入列及其顺序、记录数和记录顺序；若输入没有“审核状态”列，输出只额外增加该列。除“英文翻译”和“审核状态”外，原有列值与输入完全一致。
- **SC-002**: 输出 CSV 中 100% 的非省略词条在任务标记为完成前均有非空英文翻译。
- **SC-003**: 所有与适用参考术语匹配的词条单词均采用参考资料中符合 comment 和使用场景的英文译法；无法判定的冲突均进入人工审核。
- **SC-004**: 所有待审候选在草稿中均标明待审且不能被误认为已批准；草稿存在 CSV 译文待审记录时明确标记未完成；所有译文审核结果均能关联到涉及的词条记录，增量术语文档的后续审核不阻止 CSV 完成。
- **SC-005**: 所有达到高频门槛的未知词条均出现在独立增量参考资料中，且输入参考工作簿保持未修改。
- **SC-006**: 对无效 UTF-8、必需列缺失、参考 sheet 缺失或输出写入失败的输入，系统给出可定位的问题说明，且不报告为成功完成。

## Assumptions

- 输入 CSV 由用户在每次运行时指定；一次运行处理一个 CSV 文件。
- UTF-8 BOM 可作为 UTF-8 输入接受；输出采用 UTF-8 编码并保留输入的列结构。
- 输入 CSV 已包含“英文翻译”列；若缺失，系统报告错误而不是创建可能拼错的列。
- 输入 CSV 使用 `词条`、`comment`、`词条来源` 作为相应列头。
- 指定参考工作簿以原始 xlsx 文件保存在仓库 `assets/glossary/常用注意要点清单.xlsx`，后续作为版本化资产随 Git 仓库分发；运行时只读。
- 指定参考工作簿中的有效说明 sheet 名为 `翻译简写说明`。
- 高频按同一单词与 comment 组合在本次 CSV 中出现至少 3 次计算。
- “审核状态”只跟踪 CSV 当前译文是否需要或完成了 HITL；增量术语文档由用户在翻译后单独审核，不影响 CSV 的完成状态。
- 除用户另行指定外，翻译输出放在输入文件同目录，名称使用 `<原文件名>_translated.csv`。
- 增量参考文档以新的 `.xlsx` 文件输出到翻译输出所在目录，并供用户审核后手动合并；原始工作簿只读。
- 词条中无法可靠分词或缺少 comment/使用场景而可能改变含义的部分进入 HITL，不依赖静默猜测。
- 中文词条通常是 UI 短语或片段而非完整句子；jieba 分词用于术语识别，不代表将分词结果按原顺序机械拼接成英文。
- 参考条目“伪代码术语”字段值为“是”代表该词不是可全局固定切分和译法的静态术语；例如 `xxx配置` 在列名语境且备注允许省略“配置”时可译为 `Platform Tool`。
- “翻译省略”工作表作为翻译规则参考；规则要求省略某个词或后缀时，仍按规则完成英文翻译，不将整行误判为空翻译。
- 对不同中文词项，系统使用 embedding 稠密向量语义相似度寻找中文语义相近的近义词候选，阈值为 0.7；相似度仅提供审核提示，不代替人工实体判定或授权翻译修改。
- 相同中文词项在不同 comment 下发生的译文冲突按语境冲突提交 HITL，不依赖近义词相似度阈值。
