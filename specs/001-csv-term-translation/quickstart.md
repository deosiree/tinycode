# Quickstart: CSV 词条翻译

本指南用于实现完成后的端到端验收。它不代表当前仓库已经实现了翻译功能。

## Prerequisites

- Node.js 22.19 或更高版本。
- 在仓库根目录执行 npm ci。
- 翻译 skill 使用当前 TinyCode Agent 模型。
- 翻译请求可自动接收词条、comment、词条来源及匹配到的术语说明；不发送无关 CSV 行或无关工作簿内容。
- 近义词提示使用 OpenAI Embeddings API；运行前通过环境变量设置 OPENAI_API_KEY。不要把密钥写入仓库。
- 仓库包含 assets/glossary/常用注意要点清单.xlsx 及四个指定 sheet。

## Run scenario

1. 在仓库根目录启动 TinyCode：

        npm run dev

2. 提供一个包含词条、comment、词条来源、英文翻译列的 UTF-8 CSV 路径，并要求使用 csv-term-translation skill。
3. 检查 Agent 的预检结果：目标语言为英文，参考工作簿路径为仓库内版本化资产，输入文件未被修改；TUI 启动翻译任务后自动授权本次任务的 Embeddings 请求，不弹确认；headless `-p` 在交互式 TTY 中通过确认回调提示一次，授权覆盖任务内后续所有请求。无交互 TTY 时不得发出请求并应报告未完成。
4. 对待审核项检查字段：单词、comment、词条来源、翻译、翻译描述、使用场景、utf-8的字节长度、字符长度。
5. 对相似度达到 0.7（含）的不同中文词项确认是否为同一实体；对于相似度低于 0.7 或相同词项不同 comment 的冲突，审核拟议译文修改后再批准。
6. 检查同目录输出文件 `<原文件名>_translated.csv` 和 `<原文件名>_translated_glossary_delta.xlsx`。CSV 保留输入列序和记录顺序，并含“审核状态”“错误说明”两列；模拟失败时原因写入对应行的“错误说明”，待审或失败记录不得标记为完成。
7. 对相同输入重复运行，确认复用同一输出路径、保留已批准记录，并且原始 CSV 与参考工作簿未变化。
8. 使用包含伪代码术语的 fixture 验收翻译约束和三级检查：该术语不加入 jieba 自定义词典；翻译 prompt 和对应 judge 仅收到当前候选实际命中的参考条目，未命中的伪代码术语不得进入；全部候选依次通过脚本和 judge 检查；未通过的候选保留失败原因、任务未完成且不进入抽样；每批对通过项随机抽查 `max(1, ceil(候选数 × 5%))` 条。模拟抽查发现备注不符时，确认该批全部伪代码术语候选进入 HITL 复核，复核完成前结果保持未完成。
9. 使用包含 `{}`、`{:.3f}`、`%1` 和 `%2` 的词条验收占位符保护：花括号占位符保持原文、数量及顺序；编号百分号占位符保持标识、格式及数量但可重排。模拟缺失、损坏或重复占位符，确认候选保留失败原因且任务未完成。
10. 模拟同批单个候选及一个模型批次调用失败，确认失败候选和原因写入对应行的“错误说明”，同批其他独立候选与后续批次继续处理、每批结果仍落盘，最后整体任务标记未完成。

## Deterministic checks

使用本地 fixture 和模型/Embedding mock，不调用真实模型或 Embeddings API：

    npm test -- tests/term-translation
    npm run typecheck
    npm run lint
    npm run build

预期：CSV 引号/BOM/多行字段正确往返；无效 UTF-8、缺失列和缺失 sheet 不报告成功；0.699 与 0.7 的阈值行为不同；花括号占位符原文、数量和顺序保持，`%1`/`%2` 标识、格式和数量保持且允许重排，校验失败阻止完成；同一冲突组汇总为一个 HITL 审核事项，所有冲突仍须人工决定；TUI 在任务启动时自动授权本任务 Embedding 请求且不弹确认，headless TTY 通过确认回调取得一次授权、无交互 TTY 时拒绝请求并报告未完成；1001 条输入拆成两个批次，任一批翻译与 LLM judge 模型调用合计并发不超过 10；完成批次先落盘；重跑不产生第二个输出文件，也不覆盖已批准译文；伪代码术语候选全部经过脚本和 LLM judge，未通过者记录失败原因并阻止完成、排除抽样；通过者每批随机抽查 5%（向上取整且至少 1 条），抽查发现备注不符时升级为该批全量 HITL 复核。
