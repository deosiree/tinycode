# Skill Workflow Contract

## User input

- 用户提供一个 UTF-8 CSV 路径；一次运行只处理一个 CSV。
- 目标语言固定为英文。
- 用户不必提供参考工作簿路径；skill 使用仓库内 assets/glossary/常用注意要点清单.xlsx。
- 输入 CSV 必须有词条、comment、词条来源、英文翻译列。系统不得猜测缺失列。

## Processing contract

1. 先校验编码、必需列、参考工作簿和指定 sheet；输入无效时报告具体问题，不将任务标记为成功。
2. 优先匹配完整词条和适用语境；否则用 jieba 分词，静态参考术语加入自定义词典，伪代码术语值为“是”的词不加入。
3. 使用适用参考译法；其余候选由当前 TinyCode Agent 模型依据 comment、来源及当前词条实际匹配到的参考条目翻译。批量调用只附带本批词条命中的参考项，不发送整份词典或无关条目。若匹配到“伪代码术语=是”的参考项，仅将该项属性、尤其备注，放入该词条的翻译 prompt；不将该词加入 jieba 自定义词典，也不把该约束应用于未命中该词的词条。模型可自动接收这些字段，不逐次确认；不发送无关 CSV 行或无关工作簿内容。
4. 每批最多处理 1000 条记录，翻译与 LLM judge 模型调用合计并发上限为 10；整批完成后将结果写入固定输出 CSV，再处理下一批。
5. 对相同翻译的候选冲突运行 embedding 语义提示。TUI 启动翻译任务时自动授权本次任务全部去重中文词项，无需弹窗或等待用户操作；headless 通过交互式 TTY 的确认回调取得一次明确授权。授权覆盖本次任务后续 Embeddings API 请求，不因 API 请求重复提示，也不受通用权限模式或记忆授权替代。拒绝或无交互 TTY 时不发送，相关冲突保留人工审核并报告任务未完成。不同中文词项相似度达到 0.7（含）时提示可能近义并请求 HITL，低于 0.7 时建议不同译法；所有冲突均须人工审核。
6. 按冲突组汇总同类审核记录，在同一个 HITL 审核事项中展示该组全部相关记录和拟议变更；不相关冲突不得合并。批准任何冲突解决译文前，须等待用户对相关事项作出明确决定。相似度不得自动授权写入。
7. 对使用伪代码术语参考项的候选，依次对 100% 候选执行脚本检查和 LLM judge 检查；judge 只接收当前候选实际匹配的伪代码术语属性和备注作为核对依据，不接收整份术语表。未通过的候选保留为失败草稿并记录原因，任务标记为未完成，不自动批准，也不纳入抽样。每批对通过前两层的候选随机抽查 5%，向上取整且至少 1 条。抽查发现一条不符合参考备注时，将该批所有伪代码术语候选交由 HITL 全批复核；全批复核完成前不得报告该批或任务完成。没有通过前两层候选的批次不执行 HITL 抽查。
8. 所有英文译文都执行占位符脚本校验：花括号占位符保持原文、数量及原序；`%1`、`%2` 等编号占位符保持标识、格式及数量，但可按英文语序重排。缺失、损坏或数量不符时，保留失败候选和原因并将任务标记为未完成。
9. 单个候选翻译调用或检查失败时，保留候选与原因并继续同批其他独立候选和后续批次；每批处理结束后先保存当前输出。全部批次处理后仍有失败时，整体任务报告未完成。
10. 生成固定命名的 CSV 副本及高频未知词增量工作簿；原 CSV 和版本化参考工作簿保持只读。

## Output contract

- CSV：输入所在目录，文件名为原文件名加 _translated 后缀并保留 .csv。
- 增量工作簿：与 CSV 同目录，文件名为原文件名加 _translated_glossary_delta 后缀并使用 .xlsx。
- CSV 保留原始列序、记录数和记录序；更新英文翻译，并包含“审核状态”和“错误说明”列，缺少时按此顺序在末尾追加。错误说明逐行记录翻译调用或自动检查失败原因，无失败时留空。
- 每行审核状态为无需审核、待审核或已批准。存在任何待审核或空译文时，结果是草稿/未完成。
- 若增量资料待审但 CSV 译文已全部审核完成，CSV 可标记为完成。
- 重跑同一输入时更新同一目标文件并复用未变记录的已批准决定，不创建重复副本。

## HITL record

每个待审记录必须提供：

| 字段 | 类型 |
|---|---|
| 单词 | string |
| comment | string |
| 词条来源 | string |
| 翻译 | string |
| 翻译描述 | string |
| 使用场景 | string |
| utf-8的字节长度 | number |
| 字符长度 | number |

同一冲突组的多条记录必须在同一个审核事项中相互识别，连同拟议变更一并呈现；不同冲突组不得合并为一项决定。缺少上下文时留空，不编造。

## Embedding service boundary

- 请求模型固定为 text-embedding-3-small，比较内容为去重后的中文词项。
- API key 从 OPENAI_API_KEY 读取，不进入配置文件、输出文件或 Git。
- TUI 启动翻译任务时自动授权该任务的全部去重中文词项，无需确认操作；headless 每次任务仅在交互式 TTY 通过确认回调授权一次。授权仅覆盖当前任务，不按 API 请求重复提示。
- TUI 的自动授权由启动翻译任务触发，不依赖通用权限模式或记忆授权；headless 用户拒绝或无交互 TTY 时不发送请求、报告任务未完成，相关冲突保留人工审核。
- 请求仅发送经确认的中文词项，不发送 comment、词条来源、整行 CSV 或工作簿备注。
- API 不可用时不得用未计算的相似度标记近义候选或将任务标记为完成；保留源文件并报告失败。
