# Skill Workflow Contract

## User input

- 用户提供一个 UTF-8 CSV 路径；一次运行只处理一个 CSV。
- 目标语言固定为英文。
- 用户不必提供参考工作簿路径；skill 使用仓库内 assets/glossary/常用注意要点清单.xlsx。
- 输入 CSV 必须有词条、comment、词条来源、英文翻译列。系统不得猜测缺失列。

## Processing contract

1. 先校验编码、必需列、参考工作簿和指定 sheet；输入无效时报告具体问题，不将任务标记为成功。
2. 优先匹配完整词条和适用语境；否则用 jieba 分词，静态参考术语加入自定义词典，伪代码术语值为“是”的词不加入。
3. 使用适用参考译法；其余候选由当前 TinyCode Agent 模型依据 comment、来源、备注和使用场景翻译。
4. 对相同翻译的候选冲突运行 embedding 语义提示。不同中文词项相似度达到 0.7（含）时提示可能近义并请求 HITL；低于 0.7 时建议不同译法。所有冲突均需人工审核。
5. 在批准任何冲突解决译文前，向用户展示涉及的全部记录和拟议变更并等待明确决定。相似度不得自动授权写入。
6. 生成固定命名的 CSV 副本及高频未知词增量工作簿；原 CSV 和版本化参考工作簿保持只读。

## Output contract

- CSV：输入所在目录，文件名为原文件名加 _translated 后缀并保留 .csv。
- 增量工作簿：与 CSV 同目录，文件名为原文件名加 _translated_glossary_delta 后缀并使用 .xlsx。
- CSV 保留原始列序、记录数和记录序；只更新英文翻译、审核状态，缺少审核状态时在末尾新增。
- 每行审核状态为无需审核、待审核或已批准。存在任何待审核或空译文时，结果是草稿/未完成。
- 若增量资料待审但 CSV 译文已全部审核完成，CSV 可标记为完成。
- 重跑同一输入时更新同一目标文件并复用未变记录的已批准决定，不创建重复副本。

## HITL record

每个待审记录必须提供：

| 字段 | 类型 |
|---|---|
| 单词 | string |
| comment | string |
| 词条来源 | string |
| 翻译 | string |
| 翻译描述 | string |
| 使用场景 | string |
| utf-8的字节长度 | number |
| 字符长度 | number |

同一冲突组的多条记录必须能在同一个审核事项中相互识别。缺少上下文时留空，不编造。

## Embedding service boundary

- 请求模型固定为 text-embedding-3-small，比较内容为去重后的中文词项。
- API key 从 OPENAI_API_KEY 读取，不进入配置文件、输出文件或 Git。
- 请求仅发送中文词项，不发送 comment、词条来源、整行 CSV 或工作簿备注。
- API 不可用时不得用未计算的相似度标记近义候选或将任务标记为完成；保留源文件并报告失败。
