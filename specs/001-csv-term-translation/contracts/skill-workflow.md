# Skill Workflow Contract

## User input

- 用户提供一个 UTF-8 CSV 路径；一次运行只处理一个 CSV。
- 目标语言固定为英文。
- 用户不必每次提供参考工作簿；首次运行将仓库内 assets/glossary/常用注意要点清单.xlsx add 到本地持久向量记忆。用户在此 skill 中将其他同格式 XLSX 作为参考资料提交时，工作流自动执行 add 和内容去重，无需额外发出 add 命令。
- 用户通过专用 `add_reference_material` AgentTool 明确提交参考文件；仅当本次 add 需要外发尚未索引的新内容或更新内容时，说明来源文件名和外发范围并请求一次授权。同来源、同内容重复提交时本地跳过，不请求授权或外发。
- 用户可通过 `manage_reference_memory` AgentTool 按来源软删除记忆，或恢复/回滚到该来源的任一保留版本；软删除来源从后续 search 排除，但本机保留其完整版本历史。
- 记忆由 Mem0 OSS TypeScript SDK 管理，连接仅监听 loopback 的本机 Qdrant 服务；服务数据持久化在 TinyCode 用户数据目录，项目以 collection、`userId` 和来源清单隔离。Mem0 SDK 与 Qdrant 服务 telemetry 均关闭；额外导入的资料不自动同步到其他机器。
- 翻译 CSV 与未审核机器译文是任务数据，不自动 add 为长期参考记忆。
- 输入 CSV 必须有词条、comment、词条来源、英文翻译列。系统不得猜测缺失列。

## Processing contract

1. 校验 CSV 编码和必需列；如本地记忆未初始化，解析基线工作簿并按 add 契约授权、索引，完成前不得开始翻译。
2. 用户将参考工作簿提交到此 skill 时自动进入 add 阶段：先在本地验证格式和 sheet、解析内容并计算来源指纹；同来源内容未变化时本地幂等跳过，不请求授权或外发。需要写入新增或变更版本时，先对该次 add 的参考文档 Embedding 外发取得一次明确授权，再将解析后的片段嵌入并按 source ID/content hash 持久化；全部写入后再原子切换 active version。原工作簿保持只读。
3. 翻译每条记录前，必须使用当前词条和 comment 对本地记忆 search，最多返回 5 条相关片段及来源定位；先优先采用适用的完整词条或词级译法，否则用 jieba 分词，静态参考术语加入自定义词典，伪代码术语值为“是”的词不加入。
4. 其余候选由当前 TinyCode Agent 模型依据 comment、来源及该条 search 命中的参考项翻译。不得将整份记忆库、完整工作簿或无关条目放入模型上下文。若命中“伪代码术语=是”的参考项，仅将该项属性、尤其备注，放入对应词条的翻译 prompt；不把该约束应用于未命中该词的词条。模型可自动接收该条输入和相关命中，不逐次确认；不发送无关 CSV 行。
5. 每批最多处理 1000 条记录，翻译与 LLM judge 模型调用合计并发上限为 10；整批完成后将结果写入固定输出 CSV，再处理下一批。
6. 每次翻译和 LLM judge 请求前都 search 本地记忆；judge 复用当前候选的相关结果，只核对实际检索到的条目。数据库或 search 失败时保留错误并停止该条模型调用，不绕过记忆继续处理。
7. 每次记忆 search 和相同翻译候选冲突的 embedding 语义判断都需要 query Embedding。记忆 search 只发送当前词项及必要 comment/场景，冲突相似度只发送去重中文词项。TUI 启动翻译任务时自动授权本次任务全部 query 文本；headless 通过交互式 TTY 的确认回调取得一次明确授权。该授权覆盖本次任务后续 search 与相似度 Embedding API 请求，不替代 add 参考文档的单次授权。拒绝或无交互 TTY 时不发送，相关翻译或冲突保留未完成状态。不同中文词项相似度达到 0.7（含）时提示可能近义并请求 HITL，低于 0.7 时建议不同译法；所有冲突均须人工审核。
8. 按冲突组汇总同类审核记录，在同一个 HITL 审核事项中展示该组全部相关记录和拟议变更；不相关冲突不得合并。批准任何冲突解决译文前，须等待用户对相关事项作出明确决定。相似度不得自动授权写入。
9. 对使用伪代码术语参考项的候选，依次对 100% 候选执行脚本检查和 LLM judge 检查；judge 只接收当前候选实际检索命中的伪代码术语属性和备注作为核对依据，不接收整份术语表。未通过的候选保留为失败草稿并记录原因，任务标记为未完成，不自动批准，也不纳入抽样。每批对通过前两层的候选随机抽查 5%，向上取整且至少 1 条。抽查发现一条不符合参考备注时，将该批所有伪代码术语候选交由 HITL 全批复核；全批复核完成前不得报告该批或任务完成。没有通过前两层候选的批次不执行 HITL 抽查。
10. 所有英文译文都执行占位符脚本校验：花括号占位符保持原文、数量及原序；`%1`、`%2` 等编号占位符保持标识、格式及数量，但可按英文语序重排。缺失、损坏或数量不符时，保留失败候选和原因并将任务标记为未完成。
11. 单个候选翻译调用或检查失败时，保留候选与原因并继续同批其他独立候选和后续批次；每批处理结束后先保存当前输出。全部批次处理后仍有失败时，整体任务报告未完成。
12. 生成固定命名的 CSV 副本及高频未知词增量工作簿；原 CSV 和参考工作簿保持只读。

## Output contract

- CSV：输入所在目录，文件名为原文件名加 _translated 后缀并保留 .csv。
- 增量工作簿：与 CSV 同目录，文件名为原文件名加 _translated_glossary_delta 后缀并使用 .xlsx。
- CSV 保留原始列序、记录数和记录序；更新英文翻译，并包含“审核状态”和“错误说明”列，缺少时按此顺序在末尾追加。错误说明逐行记录翻译调用或自动检查失败原因，无失败时留空。
- 每行审核状态为无需审核、待审核或已批准。存在任何待审核或空译文时，结果是草稿/未完成。
- 若增量资料待审但 CSV 译文已全部审核完成，CSV 可标记为完成。
- 重跑同一输入时更新同一目标文件并复用未变记录的已批准决定，不创建重复副本。
- 翻译与 LLM judge 的每次调用均能关联到 search 的条目 ID 和来源；最多注入 5 条结果。检索失败时不调用模型。
- 用户提交的参考工作簿不与翻译输出混用；add 成功后重启 TinyCode 仍可检索，来源内容变化后不返回旧版条目。

## HITL record

每个待审记录必须提供：

| 字段 | 类型 |
|---|---|
| 单词 | string |
| comment | string |
| 词条来源 | string |
| 翻译 | string |
| 翻译描述 | string |
| 使用场景 | string |
| utf-8的字节长度 | number |
| 字符长度 | number |

同一冲突组的多条记录必须在同一个审核事项中相互识别，连同拟议变更一并呈现；不同冲突组不得合并为一项决定。缺少上下文时留空，不编造。

## Embedding service boundary

- 请求模型固定为 text-embedding-3-small；记忆 search Embedding 使用当前词项及必要的 comment/使用场景，冲突相似度 Embedding 只使用去重后的中文词项。
- API key 从 OPENAI_API_KEY 读取，不进入配置文件、输出文件或 Git。
- TUI 启动翻译任务时自动授权该任务所需的记忆 search query 文本与去重中文词项，无需确认操作；headless 每次任务仅在交互式 TTY 通过确认回调授权一次。授权仅覆盖当前任务，不按 API 请求重复提示。
- TUI 的自动授权由启动翻译任务触发，覆盖记忆 search 与冲突相似度判断的 query Embedding，不依赖通用权限模式或 add 授权；headless 用户拒绝或无交互 TTY 时不发送请求、报告任务未完成，相关翻译和冲突保留未完成状态。
- 记忆 search 只发送本次任务所需的当前词项及必要 comment/使用场景；冲突相似度只发送去重中文词项。两类请求都不发送词条来源、整行 CSV 或工作簿备注。
- API 不可用时不得用未计算的相似度标记近义候选或将任务标记为完成；保留源文件并报告失败。

## Memory add/search boundary

- add/search 使用 Mem0 OSS SDK；add 采用原文模式，不启用记忆提取 LLM。Qdrant 使用 loopback REST endpoint；本机服务须将数据持久化在 TinyCode 用户数据目录、按项目 collection 隔离并关闭自身 telemetry。Mem0 SDK telemetry 在动态加载前关闭；记忆文件不进项目版本控制。
- 首次翻译时将随项目提供的 XLSX add 为基线；用户提交参考 XLSX 时显式 add。每次 add 仅在需要外发尚未索引的新内容或更新内容时，于发送前取得一次授权；重复且内容未变化时本地跳过，不请求授权或发送内容。
- 使用 `source ID + SHA-256 + chunk ID` 幂等；同来源同内容不重复写入。更新时先完整写入新 source version，再原子切换该来源的 active version 指针；search 只检索 active version。切换前失败保留旧版，未完成的新版本不被检索。
- 用户明确要求移除来源时，将来源标记为软删除并排除其全部版本的 search 命中；保留的旧版本可由用户选定并原子恢复为 active，供撤回或回滚。删除、恢复和回滚只改本地来源清单，不调用 Embedding API；操作失败时保留原状态。
- search 使用当前词条及 comment 查询，最多返回 5 条片段；翻译和 judge 都必须使用 search 结果，不可回退到整本工作簿。
- 待翻译 CSV、输出 CSV 和未审核译文不自动 add。只有后续经人工审核并明确以参考 XLSX 提交的内容才进入长期记忆。
- 记忆初始化、add、search、本机 Qdrant 服务不可用或持久化失败时报告未完成并阻止相关模型调用。
